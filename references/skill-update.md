# 每天检查、自动更新与回滚

本流程只维护本地`scan-marked-papers`技能。正常使用每天首次自动检查，有官方新版本自动更新；该偏好只覆盖本技能的下载、校验、备份、替换与回读验证，不扩展到批阅台业务、项目源码、部署、Git推送、上传试卷或同步课堂。用户当次明确“只查看”或“不自动更新”时优先遵从。

## 正常使用：每天首次ensure

```bash
python3 <本技能目录>/scripts/skill_update.py ensure
```

1. 先读取本机自然日与持久检查记录。同一已安装版本当天已有结果就使用本地记录，不再次联网；最新版、本地较新、网络失败或冲突等结果都按真实状态保存。未检查或跨日时再读取官方main。
2. 固定官方仓库为`leondasdasdasd/scan-marked-papers`，分发入口为main的`scan-marked-papers.zip`。先取得main提交SHA，再从同一固定提交读取SKILL.md、release-manifest.json与ZIP，防止检查和下载之间main变化。Releases/tags只作历史信息，不用过期releases/latest替代当前main，也不跟随fork或任意remote更新。
3. 比较真实语义版本：只有官方版本更高才安装；版本相同记录已核对，本地较新记录本地领先，不降级。不能把网络失败、旧缓存或页面标题当作已是最新版。
4. 安装前核对目标版本、manifest中的运行文件SHA、ZIP顶层结构与合法相对路径、必要SKILL/agents/references/scripts文件。必要文件按目标版本校验：1.10.6起包含 runtime helper，1.10.10起包含 doctor；旧版基线仍按其版本兼容校验。校验完成前不替换。manifest不包含自身的自引用哈希；不执行下载包中的未知安装脚本，不要求正式包附带测试或开发文档。
5. 用已安装release-manifest.json核对本地发行文件基线。发现用户修改或新文件覆盖冲突就保留旧版并报告具体文件，不自动强覆；无manifest的旧安装返回`baseline_missing`，不动态把本地文件当官方基线，不自动覆盖。首次升至1.9.0按下文显式安装完成，之后才具备自动更新基线。
6. 只更新本技能，将备份置于技能发现目录之外；保留本地额外内容，保护登录态、Cookie、令牌、任务checkpoint、试卷及其他技能。替换后核对实际版本与文件哈希；失败恢复原备份并验证回滚，不删用户旧目录。
7. 更新成功后重新读取实际安装SKILL.md及本次需要的参考，CLI业务入口重载更新后的代码；不在一次业务操作中混用新旧契约。无变化、同日复用通常无需打断老师，只在实际升级、冲突或影响本次处理的失败时简要说明。

这不是后台定时器；只有使用技能时执行，每天首次检查后当日免重复。网络失败也记录当天失败，避免每个步骤重复联网；保持旧版可用时继续已授权且兼容的业务，有具体不兼容再保留阻塞。次日首次使用再检查；老师明确要求当天重试时才用force。

## 本地状态与手动刷新

```bash
python3 <本技能目录>/scripts/skill_update.py status
python3 <本技能目录>/scripts/skill_update.py ensure --force
```

`status`离线读取已安装版本和最近检查记录，不查询GitHub、不下载安装。只问“看看版本/检查更新”优先用status；若需核对远端最新信息，只读查询官方main及固定提交元信息，不运行ensure，不下载或替换技能。

`ensure --force`跳过当天检查缓存，仍执行来源、版本、完整性和本地修改保护；只在用户明确要求立即刷新/更新或重试时使用。强制刷新不等于强制覆盖，不降级、不绕过冲突。用户明确不自动更新时，使用`PAPERFLOW_AUTO_UPDATE=0`关闭；`false`或`off`同样有效，正常CLI入口与独立ensure均遵从，force也不会绕过该开关。不要求老师自行配置，由智能体在本次执行环境设置并保留约束；只有用户明确重新启用才恢复。

安装目录中的正常CLI业务调用会自动ensure；源码开发Git checkout不会自更新以免覆盖开发树。离线`--help`、api-list、collect和带本地metadata的离线review不触发联网或更新。独立调用ensure后若有更新，智能体还须重新读技能；CLI重载代码不能代替指令回读。

## 结果读取与缓存

更新记录按实际安装目录隔离，存于系统用户缓存目录中的`scan-marked-papers/<目录指纹>/state.json`，不放入技能发现目录或业务checkpoint。优先XDG_CACHE_HOME，其次LOCALAPPDATA，否则使用用户目录的`.cache`。记录保留检查日期、时间、已安装/远端版本、固定提交与结果，权限由更新工具限制；无需老师指定路径。

| outcome | 含义与处理 |
| --- | --- |
| `up_to_date` | 当日已联网核对，官方与本地版本相同，继续处理 |
| `local_version_newer` | 本地版本高于官方，保留本地，不降级 |
| `updated` | 新版已校验并安装，重新读实际技能；CLI重载新代码后继续 |
| `cached_today` | 同版本当天已检查，此次未联网；读取previous_outcome，不把历史失败解释为最新 |
| `baseline_missing` | 旧安装缺manifest，保留旧版，按显式安装流程先升级到1.9.0 |
| `local_changes_preserved` | 本地发行文件或新增目标文件有冲突，保留原内容，集中报告冲突文件 |
| `update_failed` | 网络、校验或替换失败，保留旧版并读error；不能说最新版。若error=update_rollback_failed，保留恢复目录并报告具体恢复缺口 |
| `auto_update_disabled` | 用户已用PAPERFLOW_AUTO_UPDATE=0/false/off关闭，未联网、未替换；force也不绕过 |
| `development_checkout` | 当前目录是开发Git checkout，未联网、未替换 |
| `update_in_progress` | 同一安装有另一次更新，避免并发业务写入；按CLI提示稍后接续，不另启升级或强抢锁 |
| `update_status` | 离线状态查询，不代表本次已与GitHub核对 |

## 首次安装或旧版显式升级

用户明确安装/升级已授权下载、校验与替换本技能，不再逐步询问；旧版无manifest时不能借此绕过已有本地修改。有现成命令和下载能力时，优先从同一固定官方提交直接下载归档或 ZIP；也可用 GitHub API 的原始内容由程序解码。必须保留文件原始字节，不通过模型转录、改写或逐字抄写源码来安装。

- 记录官方main固定提交、SKILL版本、包SHA-256与顶层结构。从该提交取包，核对目标版本及release-manifest.json；首次1.9.0包必须含有效manifest和必要运行文件。
- 备份旧技能到所有技能发现根目录及其子目录之外的受控位置，保留本地修改；不要把含 SKILL.md 的 backup 留在 skills 下，避免加载器误命中旧版。仅比较可能被覆盖的相关文件；已有改动冲突就列出并停止，除非用户对这些具体冲突明确选择覆盖。不得把本地自改文件直接记录为官方baseline。
- 安装到当前工具实际技能目录，仅替换本技能。目标环境已有quick_validate.py时运行；没有时按frontmatter、版本、agents元信息、manifest哈希与必要文件核验，不要求办公产品安装Codex或新运行时。
- 安装完成后按固定提交的 manifest 逐个验证发行文件，并回读实际 SKILL.md、版本、安装路径与来源证据；任一哈希不一致就报告具体文件，不能只靠 metadata 声称成功。过程中尚在写入的快照与最终结果分别记录，不把中间不匹配说成最终失败。仅修复本轮引入且当前仍失败的安装项，保留原备份及必要恢复副本，不覆盖用户无关修改。
- 区分“已下载”“已安装并验证”；失败回滚并报告真实结果，不把文件存在当新版本生效。验真后本轮已有明确业务请求就立即继续，不再询问是否开始，也不重复下载安装。清理本次无需保留的临时包，保留必要回滚备份、用户原有服务、会话、checkpoint和材料。

## 无Python或办公产品能力不足

只使用产品现有命令、下载、文件和技能管理工具；如果能完成相同的固定提交校验、同日持久记录、冲突保护和替换，可以按同一逻辑执行。只有导入ZIP界面、无命令或无法可靠写回技能时，说明“当前环境不能自动更新”，保留当前安装并给已核实的更新入口，不反复索要技术参数、不擅装Python、插件或运行时，不把下载成功当作已升级。

## 数据与授权边界

检查记录只保存日期、版本、提交、校验摘要与结果等非敏感更新元信息，不保存账号密码、Cookie、授权链接、学生答案或任务正文。缓存和备份不放入技能发现目录、Git仓库或业务checkpoint。自动更新既不授权创建批次、改变教师已选终点或同步课堂，也不授权修改共享服务。只有本次明确要求Git提交/推送才另行执行，不由自动升级流程触发。
